STORAGE HELP

A place for your encrypted backups.

What QStorage buckets are, which access you need, and how to fix setup problems.

What is a bucket?

A bucket is a named container in QStorage, similar to a top-level folder. QVault stores encrypted files inside it. Enter the bucket’s name, not its web address.

Bucket names are shared across QStorage accounts. If a name is taken, choose another. New buckets created by QVault request private access.

Why can’t QVault create mine?

An access key is not automatically allowed to do everything in your account. It needs permission to create a bucket. It also needs access to inspect the bucket before QVault can confirm it is available.

  1. Open QConsole and review the permissions for the access key you entered. Ask the account administrator if you cannot change them.
  2. Allow bucket creation, then enter the access details in QVault and try again.
  3. Alternatively, create the bucket manually as described below. The key still needs access to inspect and use that bucket.

Wrong or expired credentials are a separate problem. Fix those first; adding permissions will not repair a wrong secret key.

Create a bucket manually

  1. In QConsole, open Services → QStorage.
  2. Choose Create Bucket and enter a unique name.
  3. Keep access private. Do not enable public reading or writing.
  4. Return to QVault Setup, enter exactly that name and choose Save cloud storage.

QVault checks an existing bucket without changing its settings. Existing vaults are reopened and checked before updated storage access is saved. A bucket containing vault data cannot be changed without a separate migration.

Other common messages

QVault cannot check this bucket
The key cannot inspect it, the credentials may be wrong, or the account policy denies access. QVault does not treat this as a missing bucket and does not create another one.
This bucket name is already taken
Choose another name. QVault will not take over or modify someone else’s bucket.
Bucket creation could not be confirmed
The response was lost. Check the same name in QConsole first: the bucket may already exist. QVault does not automatically repeat the creation request.
Bucket was accepted, but access is not confirmed
Creation may have succeeded, but the follow-up check failed. Check permissions on that same bucket.
For administrators: exact permission names

QStorage uses S3-compatible API names. That is an API naming convention, not a request to create an Amazon account or store your files with Amazon.

  • s3:CreateBucket: creates a new bucket.
  • HeadBucket access: checks whether the selected bucket is accessible. Grant the relevant inspection access in your QStorage policy.
  • s3:GetObject and s3:PutObject: read and write QVault’s encrypted objects.

Permissions can be scoped to the intended bucket and QVault object prefix. The setup helper does not need bucket deletion and does not make an existing bucket public.
